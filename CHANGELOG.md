# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [4.0.0] — 2026-11-28

### Добавлено

- Полностью новый интерфейс на **C# / .NET 8 / WPF** вместо Tkinter: собственный заголовок, капсула GPU, стеклянные карточки, градиент RTX Green → Cyan и эффекты Mica/акрил.
- Очередь с Drag & Drop файлов и папок, поиском, асинхронными миниатюрами и метаданными `ffprobe`, бейджем VFR и прогрессом стадий.
- «Тест 5 сек» — реальный превью-рендер фрагмента с диалогом сравнения «До / После».
- Менеджер пресетов, действие после завершения (уведомление / сон / выключение) и пили-переключатели FPS/пресета/кодека/Enhance.
- Диагностика GPU в фоне: радиальный индикатор, полоса VRAM, спарклайны и таблица компонентов через `nvidia-smi`.
- Журнал с подсветкой INFO/WARNING/ERROR, поиском, экспортом в `.txt`, копированием CLI-команды и карточкой итоговой проверки `ffprobe`.
- Диалог «О программе»: версия, автор, GitHub, MIT, `NOTICE.md` и проверка обновлений через GitHub Releases.

### Изменено

- Движок вынесен в отдельный headless-процесс `rtx_engine.exe` (PyInstaller, `src/rtx_engine.spec`); при его отсутствии GUI запускает `python -u rtx_media_master_v35.py`.
- Сборка переведена на `Microsoft.NET.Sdk`; `build.ps1` теперь собирает WPF-GUI, CLI-движок и MSI одной командой.
- Версия продукта и MSI обновлена до `4.0.0`; проверка обновлений сравнивается с `4.0.0`.

### Исправлено

- Критический сбой запуска: неверный ключ стиля `WinButton.Close` в заголовке окна.
- Пустые вкладки «Настройки» и «Журнал»: добавлены code-behind с `InitializeComponent()`.
- Падение при открытии «Диагностики»: `DiagnosticsView` теперь получает `DataContext` через `DataContextChanged`.
- Ошибка привязки `VramPercent` (`TwoWay` к свойству только для чтения) и неверный `StringFormat` VRAM.
- Отсутствие страницы при запуске: первая вкладка «Очередь» отображается сразу.
- Иконки бокового меню теперь используют шрифт Segoe MDL2 Assets; «Справка» открывает README вместо окна «О программе».
- Скриншоты в `docs/screenshots` пересняты с реального WPF-интерфейса v4, описание README приведено к v4.

### Удалено

- Старый Tkinter-GUI и связанные с ним зависимости/компоненты.

## [3.5] — 2026-11-26

### Исправлено

- Лицензионное соглашение MSI больше не содержит Lorem ipsum: в диалог вшит настоящий текст MIT License (Copyright (c) 2026 x_kitaikuyo_x) через `WixUILicenseRtf`.


### Установщик

- В MSI появился стандартный диалог выбора папки установки (`WixUI_InstallDir`).
- Включено высокое сжатие CAB (`CompressionLevel=high`) и более лёгкий `ffprobe.exe` из FFmpeg Essentials: установщик уменьшен с 584 до 539 МБ (−7.7%).
- Полнофункциональный `ffmpeg.exe` сохранён: в нём доступны libsvtav1 и libvvenc.

### Исправлено по аудиту (v3.5)

- Насос событий GUI больше не умирает от любого исключения в обработчике: `after()` перепланируется в `finally`, каждое событие обрабатывается в отдельном `try/except`.
- Разрешение сохраняется и загружается в одном формате (значения, а не подписи); геометрия окна сохраняется вместе с координатами; миграция профиля не перезаписывает пользовательские значения.
- Переключатель `enhance` v3.5 работает независимо от устаревшей опции «Резкость»; качество `21` добавлено в список; выходной файл всегда `.mp4`.
- Кнопка «Отмена» и закрытие окна теперь останавливают процессы движка: добавлен реестр активных `Popen` и `cancel_active_processes()`.
- Bootstrap блокирует запуск, если движок v3.5 не импортирован; `preflight_check` проверяет диск `%TEMP%` и не требует RIFE для даунскейла.
- ETA и скорость в статус-баре обновляются во время рендера; целевое разрешение из GUI наконец передаётся в движок.


### Добавлено

- Полноценное GUI-приложение v3.5 со встроенным движком: настройки кодека (`auto/av1/hevc/vvc/h264`), пресета (`compact/balanced/quality`), GPU, `Enhance`, целевого FPS вверх/вниз; прогресс и итоговая статистика размера до/после в строке состояния.
- CLI сохранён как внутренний бэкенд `--headless` для автоматизации и диагностики; основным продуктом остаётся оконная программа с MSI-установщиком.
- Движок: диагностика FFmpeg/FFprobe/RIFE/Vulkan, модель `rife-v4.6`, нормализация VFR→CFR, перекрывающиеся чанки с обработкой сцен-резов `scdet`, точные длительность и число кадров.
- Современные кодеки с 10-bit: AV1 (`libsvtav1`, `av1_nvenc`), HEVC (`libx265`, `hevc_nvenc`), VVC (`libvvenc`), H.264 как фолбэк; корректные CQ/mbr/bitrate_cap.
- `--enhance`: `bwdif`, `zscale`, `hqdn3d`, `cas=0.25` для деинтерлейса, цвета и лёгкой резкости.

### Исправлено

- `av1_nvenc`: правильная шкала CQ 0–63 (38/34/30 вместо почти lossless 26), явные `-b:v` и `-maxrate`.
- `libsvtav1`: предел битрейта задаётся через `mbr=` внутри `-svtav1-params` (в CRF-режиме `-maxrate` игнорируется).
- Временные каталоги чанков гарантированно удаляются через `TemporaryDirectory` и `try...finally`.
- Windowed-сборка: корректная работа `--headless` при `sys.stdout=None`, отдельный crash-лог.
- Все внешние процессы (ffmpeg, ffprobe, rife-ncnn-vulkan) запускаются с `CREATE_NO_WINDOW` / `SW_HIDE`: чёрные окна консоли больше не появляются поверх GUI.
- Рантайм-тест энкодеров использует кадр 256×144: NVENC отклонял 64×64 как слишком маленький, из-за чего 4K-кодирование уходило на CPU `libx265`; теперь выбирается `hevc_nvenc` (`p010le`, `p6`).
- Автовыбор кодеков стал hardware-first: сначала GPU (AV1/HEVC/H.264 NVENC/QSV/AMF), затем программные энкодеры.
- Downscale-кодирование передаёт живой прогресс через `-progress pipe:1`; подпись скорости в GUI исправлена на `x realtime` вместо «FPS 0».


### Проверено

- 30 → 60 FPS, HEVC Main 10 (`libx265`, `--enhance`): 4.000 с, ровно 240 кадров, размер 0.576x от исходного.
- 30 → 120 FPS, AV1 (`libsvtav1`, capped CRF 28): 4.000 с, 480 кадров, размер 0.628x.
- 30 → 24 FPS, VVC (`libvvenc`): 4.000 с, 10-bit, размер 0.224x.
- GUI запускается с заголовком «RTX Media Master v3.5 - Video Interpolator»; MSI устанавливается в `C:\Program Files (x86)\RTX Media Master`.

## [3.1.1] — 2026-11-25

### Исправлено

- Запуск MSI-версии больше не падает с `PermissionError [Errno 13]` при создании
  `session_runtime.log` в `Program Files`: журнал, настройки, crash-лог и временные
  архивы перенесены в доступный для записи каталог `%APPDATA%\RTX Media Master`.
- Настройки из прежнего расположения автоматически переносятся при первом запуске.
- Если бинарники отсутствуют в каталоге программы, они скачиваются в пользовательский
  каталог без прав администратора.
- Файловый лог при недоступности больше не блокирует запуск программы.

## [3.0.0] — 2026-11-25

### Добавлено

- Автономная сборка PyInstaller и MSI-установщик: Python не нужен.
- GUI в стиле Windows 11: NavigationView, CommandBar, страницы «Очередь»,
  «Диагностика», «Параметры», «Журнал», темы AI Dark / Windows / светлая / тёмная.
- Режимы обработки: RIFE ncnn-vulkan (Vulkan GPU), Turbo GPU, AI CPU minterpolate.
- Очередь файлов с поиском, инспектор видео, прогресс и ETA.
- Диагностика комплектующих и телеметрия GPU/VRAM через nvidia-smi.
- Профили «качество ↔ размер», NVENC/AMF/AV1 с программным фолбэком.
- WiX-генератор и скрипт `build.ps1` для воспроизводимой сборки MSI.

### Исправлено

- Определение доступных энкодеров: NVENC/AMF теперь корректно обнаруживаются.
- Поиск моделей RIFE внутри вложенных папок архива.
- Прогресс кодирования через `-progress pipe:1`, корректный ETA.
- Сохранение настроек вынесено в главный поток GUI.
-AV1: корректные параметры libsvtav1/libaom-av1 и фолбэк SVT → AOM.
- Обработка битых `settings.json` и отмены операций.

### Известные ограничения

- AV1-кодирование на RTX 3050 выполняется программно (libsvtav1) — медленнее NVENC.
- Для RIFE необходим GPU с поддержкой Vulkan.

- 10-секундный 4K-клип, `--codec auto`: `hevc_nvenc / p010le`, 19.2 с, 4.8 МБ.
